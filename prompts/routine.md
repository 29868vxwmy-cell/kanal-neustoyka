# Ежедневная задача Claude: черновики для канала

Эту инструкцию выполняет задача Claude по расписанию (каждый день в 06:00 МСК).
Задача пишет черновики в `posts/queue/` и отправляет их в ветку `main`.
Сервер забирает их каждые 10 минут, бот присылает Максу на одобрение или публикует сам.

## Что сделать за один запуск

1. Новости. Проверь источники за последние сутки:
   - решение Банка России по ключевой ставке: https://www.cbr.ru/press/keypr/ и календарь https://www.cbr.ru/DKP/cal_mp/;
   - новые законы про ГК, АПК, госпошлины, мораторий на неустойку: http://publication.pravo.gov.ru/;
   - постановления Пленума и обзоры практики ВС про неустойку и долги: https://vsrf.ru/.
   Если есть новость по теме канала (неустойка, ст. 395 ГК, ключевая ставка, претензия, взыскание
   долга с покупателя, судебный приказ), напиши срочный пост с `urgent: true` и сегодняшней датой.
2. Плановые посты. Дни постов — пн, ср, пт. Для каждого такого дня в ближайшие 14 дней, на который
   в `posts/queue/` нет файла с этим `publish_on`, напиши пост. Тему бери из `content/topics.md`
   (первую, которой ещё нет среди `topic:` в очереди) и отметь её там как взятую.
   Пока в очереди есть файлы без `publish_on` (стартовые посты), плановые не пиши — только срочные.
3. Проверка. Для каждого нового файла:
   - узнай текущую ключевую ставку на https://www.cbr.ru/press/keypr/;
   - запусти `python3 -m bot.kanal check --rate <ставка> posts/queue/<файл>.md` — должно быть `OK`;
   - запусти `python3 -m unittest -q`.
   Если проверка не проходит и исправить честно нельзя (нет источника), всё равно положи файл:
   бот отправит его Максу на одобрение с пометкой. Не обходи проверку.
4. Коммит в `main` с сообщением `Черновики канала <дата>`, push. Если писать нечего — ничего не коммить.

## Формат файла

Имя: `<дата>-<коротко-латиницей>.md`, id совпадает с именем без `.md`
(только a-z, 0-9, дефис, до 50 знаков).

```
---
id: 2026-11-02-sudebnyj-prikaz
publish_on: 2026-11-02
topic: Судебный приказ в арбитраже
sources:
  - https://... (страница, которую ты реально открыл)
---
<b>Заголовок</b>

Текст...

Норма: <a href="https://...">ст. ... ГК</a>.

👉 <a href="https://kalkulyator-neustoyki.ru/?utm_source=telegram&amp;utm_medium=channel&amp;utm_campaign=<id>">Посчитать неустойку</a>
```

Разметка — только теги Telegram: `<b> <i> <u> <s> <a href> <code> <blockquote>`. `&` в ссылках пиши как `&amp;`.

## Правила текста

- Тон — живой, с лёгкой иронией: 1–2 удачные фразы на пост, не больше. Шутим над должниками
  («деньги всё ещё „вот-вот“», «классика жанра») и над бумажной волокитой. Не шутим над законами,
  судами, цифрами, ставками и над читателем; юмор не должен искажать смысл нормы или расчёта.
  Без мемов, жаргона и обидных слов. Если шутка не придумалась естественно — лучше без неё.
  Примеры удачного тона: «пункт о пене в договоре стоит денег. Буквально.»;
  «Справку о моральных страданиях бухгалтера прикладывать не нужно.»
- Читатель — владелец малого бизнеса или бухгалтер, которому покупатель не платит по УПД. Пиши просто,
  600–1200 знаков, один пост — одна мысль, обязательно пример с цифрами, если тема позволяет.
- Каждая норма, дата и цифра — только из страницы, которую ты открыл в этом запуске. Ссылку на неё
  ставь в текст и в `sources`. Не нашёл источник — не пиши этот факт.
- Ключевую ставку бери только с сайта ЦБ. Арифметику примеров пересчитывай кодом.
- Осторожно: «по общему правилу», «если договором не установлено иное». Никаких обещаний исхода дела,
  «гарантированно», «100%», процентов побед. Не выдавай пост за юридическую консультацию.
- Никаких реальных компаний, людей и данных клиентов. Примеры — выдуманные.
- Ссылки только на источники из белого списка в `bot/posts.py` и на калькулятор.
- Не трогай код бота, скрипты и уже лежащие в очереди посты. Только новые файлы и `content/topics.md`.
